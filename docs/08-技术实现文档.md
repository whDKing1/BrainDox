# 心理健康智能分诊与辅助诊断系统 — 技术实现文档

> 版本：v1.0  
> 基于现有 BrainDox 临床决策系统扩展，从医生端工具升级为"用户端 + 医生端"全流程平台

---

## 一、项目概述

### 1.1 系统定位

将现有纯医生端的临床辅助决策系统，升级为覆盖**用户端对话问诊 → AI 分层诊断 → 医生端审核确认 → 报告自动推送**的全流程心理健康服务平台。

### 1.2 核心流程

```
用户端对话 → 意图识别 + 严重度分层
    ↓
  ┌──────┬──────┬──────┐
  L0-L1  L2    L3-L4
  ↓       ↓       ↓
轻症Agent 中症Agent 重症Agent(复用现有系统)
  ↓       ↓       ↓
  1结论   2可能性   3可能性 + 治疗方案
  ↓       ↓       ↓
  └───────┬───────┘
          ↓
       生成草稿报告 → 医生端审核工作台
                          ↓
                    ☑ 确认 → 用户端查看 + PDF自动发邮箱
                    ✗ 退回 → 备注原因 → 追问补全 → 重新提交
```

### 1.3 核心业务规则

| 规则项 | 说明 |
|--------|------|
| **全覆盖** | 不论轻重，所有对话都走对应级别的诊断 Agent 并生成报告 |
| **医生终审** | 所有报告必须经医生审核确认才生效，AI 仅为辅助 |
| **分级诊疗** | L0-L1 走轻症 Agent，L2 走中症 Agent，L3-L4 走原系统重症 Agent |
| **报告即档案** | 轻症报告使用 ICD-11 Z编码/DSM-5 V编码框架，纳入用户健康档案 |
| **轻症简洁、重症详尽** | 轻症 1 结论、中症 2 鉴别、重症 3 可能性 |

### 3.3 Agent 分层设计

```
┌──────────────────────────────────────────────────────┐
│                  入口层: 意图识别 Agent                 │
│  输入: 用户文本 → 输出: {intent, severity_level}     │
├──────────────────────────────────────────────────────┤
│                   分发路由                             │
│  L0-L1 ──→ 轻症Agent      (LLM+规则，1结论)          │
│  L2    ──→ 中症Agent      (LLM+知识图谱，2鉴别)      │
│  L3-L4 ──→ 重症Agent      (完整现有系统，3可能性)     │
│           ├── diagnosis_agent                        │
│           ├── treatment_agent                        │
│           ├── coding_agent                           │
│           └── audit_agent                            │
├──────────────────────────────────────────────────────┤
│                  输出层: 报告生成 Agent                 │
│  合并诊断结果 → 生成结构化报告草稿                      │
└──────────────────────────────────────────────────────┘
```

### 4.3 数据库创建 SQL（核心表）

```sql
-- PostgreSQL 16

-- 用户表
CREATE TABLE users (
    id UUID PRIMARY KEY DEFAULT gen_random_uuid(),
    email VARCHAR(255) UNIQUE NOT NULL,
    password_hash VARCHAR(255) NOT NULL,
    name VARCHAR(100) NOT NULL,
    role VARCHAR(20) NOT NULL CHECK (role IN ('patient', 'doctor', 'admin')),
    phone VARCHAR(20),
    avatar_url VARCHAR(500),
    is_active BOOLEAN DEFAULT true,
    created_at TIMESTAMP DEFAULT NOW(),
    updated_at TIMESTAMP DEFAULT NOW()
);
CREATE INDEX idx_users_email ON users(email);
CREATE INDEX idx_users_role ON users(role);

-- 会话表
CREATE TABLE conversations (
    id UUID PRIMARY KEY DEFAULT gen_random_uuid(),
    user_id UUID NOT NULL REFERENCES users(id) ON DELETE CASCADE,
    status VARCHAR(20) NOT NULL DEFAULT 'active'
        CHECK (status IN ('active','awaiting_review','completed','closed')),
    severity_level VARCHAR(5) CHECK (severity_level IN ('L0','L1','L2','L3','L4')),
    intent_category VARCHAR(50),
    started_at TIMESTAMP DEFAULT NOW(),
    ended_at TIMESTAMP,
    created_at TIMESTAMP DEFAULT NOW()
);
CREATE INDEX idx_conv_user_id ON conversations(user_id);
CREATE INDEX idx_conv_status ON conversations(status);
CREATE INDEX idx_conv_created ON conversations(created_at);

-- 消息表
CREATE TABLE messages (
    id UUID PRIMARY KEY DEFAULT gen_random_uuid(),
    conversation_id UUID NOT NULL REFERENCES conversations(id) ON DELETE CASCADE,
    sender_type VARCHAR(10) NOT NULL CHECK (sender_type IN ('user','ai','system')),
    content TEXT NOT NULL,
    metadata JSONB DEFAULT '{}',
    created_at TIMESTAMP DEFAULT NOW()
);
CREATE INDEX idx_msg_conv_id ON messages(conversation_id);
CREATE INDEX idx_msg_created ON messages(created_at);

-- 意图分类结果表
CREATE TABLE intent_classifications (
    id UUID PRIMARY KEY DEFAULT gen_random_uuid(),
    conversation_id UUID NOT NULL REFERENCES conversations(id) ON DELETE CASCADE,
    message_id UUID REFERENCES messages(id) ON DELETE SET NULL,
    intent VARCHAR(50) NOT NULL,
    severity_level VARCHAR(5) NOT NULL CHECK (severity_level IN ('L0','L1','L2','L3','L4')),
    confidence_scores JSONB DEFAULT '{}',
    triggered_route VARCHAR(20) NOT NULL CHECK (triggered_route IN ('mild','moderate','severe')),
    created_at TIMESTAMP DEFAULT NOW()
);

-- 诊断结果表
CREATE TABLE diagnosis_results (
    id UUID PRIMARY KEY DEFAULT gen_random_uuid(),
    conversation_id UUID NOT NULL REFERENCES conversations(id) ON DELETE CASCADE,
    severity_level VARCHAR(5) NOT NULL CHECK (severity_level IN ('L0','L1','L2','L3','L4')),
    agent_type VARCHAR(20) NOT NULL CHECK (agent_type IN ('mild','moderate','severe')),
    primary_diagnosis JSONB NOT NULL,
    differential_list JSONB DEFAULT '[]',
    clinical_notes TEXT,
    raw_llm_output TEXT,
    created_at TIMESTAMP DEFAULT NOW()
);

-- 报告表
CREATE TABLE reports (
    id UUID PRIMARY KEY DEFAULT gen_random_uuid(),
    conversation_id UUID NOT NULL REFERENCES conversations(id) ON DELETE CASCADE,
    user_id UUID NOT NULL REFERENCES users(id) ON DELETE CASCADE,
    doctor_id UUID REFERENCES users(id) ON DELETE SET NULL,
    report_type VARCHAR(10) NOT NULL CHECK (report_type IN ('mild','moderate','severe')),
    status VARCHAR(20) NOT NULL DEFAULT 'draft'
        CHECK (status IN ('draft','pending_review','approved','rejected')),
    content JSONB NOT NULL,
    doctor_comment TEXT,
    pdf_url VARCHAR(500),
    emailed_at TIMESTAMP,
    created_at TIMESTAMP DEFAULT NOW(),
    updated_at TIMESTAMP DEFAULT NOW()
);
CREATE INDEX idx_report_user_id ON reports(user_id);
CREATE INDEX idx_report_doctor_id ON reports(doctor_id);
CREATE INDEX idx_report_status ON reports(status);
```

### 5.2 核心接口详细定义

#### POST /api/v1/chat/send — 发送对话消息

**Request**：
```json
{
  "conversation_id": "uuid-or-null",
  "content": "我最近总是睡不好，心情很差",
  "user_id": "uuid"
}
```

**Response**：
```json
{
  "conversation_id": "uuid",
  "reply": {
    "content": "听起来你最近的状态不太好，能跟我说说这种情况持续多久了吗？",
    "type": "question",
    "intent": {
      "category": "倾诉",
      "severity_level": "L1",
      "confidence": 0.92
    }
  },
  "route_hint": "mild"
}
```

**处理流程**：
1. 若无 conversation_id 则创建新会话
2. 调用意图识别服务分类用户输入
3. 根据意图 + 严重度决定回复策略
4. 若判定为 L3-L4，启动重症诊断 Agent 链路
5. 保存消息到数据库

#### POST /api/v1/doctor/reviews — 提交审核结果

**Request**：
```json
{
  "report_id": "uuid",
  "action": "approved",
  "comment": "诊断准确，建议调整用药剂量",
  "doctor_id": "uuid"
}
```

**Response**：
```json
{
  "report_id": "uuid",
  "status": "approved",
  "reviewed_at": "2026-05-31T10:30:00Z",
  "email_status": "pending"
}
```

**处理流程**：
1. 医生身份校验
2. 更新 report 状态为 approved/rejected
3. 写入 doctor_reviews 审核记录
4. 若 approved → 触发异步任务：生成 PDF + 发送邮件
5. 若 rejected → 更新用户端对话，提示补充信息

#### POST /api/v1/internal/intent/classify — 意图识别

**Request**：
```json
{
  "text": "我最近总是睡不好，心情很差",
  "conversation_history": [
    {"role": "user", "content": "你好"},
    {"role": "ai", "content": "你好，有什么可以帮你的？"}
  ]
}
```

**Response**：
```json
{
  "intent": "倾诉",
  "intent_confidence": 0.92,
```

## 六、意图识别模块详细设计

### 6.1 分类体系

#### 意图分类（6 类）

| 意图 | 描述 | 示例 |
|------|------|------|
| `倾诉/宣泄` | 需要倾听，不需要建议 | "最近真的好累" |
| `求助/诊断询问` | 希望获得评估或解释 | "我这是不是抑郁了" |
| `危机信号` | 需要紧急干预 | "活着没意思" |
| `信息咨询` | 科普需求 | "焦虑症和抑郁症哪个严重" |
| `日常闲聊` | 无需医疗介入 | "今天天气不错" |
| `拒绝回答` | 用户不愿配合 | "不想说这些" |

#### 严重度分层（5 级）

| 层级 | 名称 | 特征 | 示例 |
|------|------|------|------|
| L0 | 正常波动 | 情绪有起伏，能自我调节 | "最近工作有点烦" |
| L1 | 亚健康 | 有症状但未达诊断标准，<2周 | "睡不好几天了" |
| L2 | 中度 | 符合诊断标准，功能部分受损 | "经常失眠，不想见人" |
| L3 | 重度 | 症状严重，功能明显受损 | "起不了床，什么都做不了" |
| L4 | 危急 | 有自伤/自杀/伤人风险 | "想结束这一切" |

### 6.2 技术实现方案

#### 方案选型：LLM Few-shot + 规则引擎兜底

```
输入文本
    ↓
┌─────────────────────────┐
│  规则引擎前置过滤        │
│  - 危机关键词匹配(L4)    │
│  - 闲聊模式匹配(L0)     │
│  - 明确拒绝匹配(拒识)   │
└─────────┬───────────────┘
          │ 未命中规则
    ┌─────▼──────┐
    │ LLM Few-shot │
    │ 分类 + 推理  │
    └─────┬──────┘
          │
    ┌─────▼──────┐
    │ 后处理校验   │
    │ 置信度 + 兜底 │
    └─────────────┘
```

#### LLM Prompt 模板

```
你是一个心理健康意图识别专家。请对以下用户输入进行分类。

【分类维度】
1. 意图类别：倾诉/求助/危机/咨询/闲聊/拒绝
2. 严重度等级：L0(正常) / L1(亚健康) / L2(中度) / L3(重度) / L4(危急)
3. 是否存在风险信号（自杀/自伤/伤人）

【判断规则】
- 任何提及自杀、自伤、不想活 → 优先判为"危机" + L4
- 含糊表达 + 无具体症状 → 倾向"倾诉"
- 询问知识类 → "咨询"
- 非健康话题 → "闲聊"

【输出格式】
{
  "intent": "类别",
  "severity_level": "Lx",
  "confidence": 0.0-1.0,
  "risk_flags": ["信号1", "信号2"],
  "reasoning": "简要推理"
}

-----
用户输入：{text}
```

### 6.3 规则引擎关键词库

```
L4 危机信号（优先级最高）：
  - 自杀、自尽、不想活、了结、轻生、跳楼、上吊、割腕
  - 遗书、告别、最后的话、活不下去
  - 杀了他/她、同归于尽

L0 闲聊信号：
  - 天气、吃饭、晚安、早安
  - 非健康话题的日常问候

拒绝回答：
  - 不想说、不愿意、别问了、算了吧
```

## 七、诊断 Agent 分层设计

### 7.1 Agent 职责对比

| 维度 | 轻症 Agent (L0-L1) | 中症 Agent (L2) | 重症 Agent (L3-L4) |
|------|-------------------|-----------------|-------------------|
| **LLM 模型** | GPT-4o-mini | GPT-4o-mini | GPT-4o |
| **知识图谱** | 不调用 | 有限调用 | 完整 GraphRAG |
| **输出结论数** | 1 个 | 2 个（鉴别诊断） | 3 个（鉴别诊断） |
| **输出内容** | 状态评估 + 建议 | 诊断评估 + 就医建议 | 完整诊断 + 治疗方案 |
| **是否生成报告** | 是（Z编码） | 是（正式诊断） | 是（完整报告） |
| **平均耗时** | <2s | <5s | <15s |

## 十一、安全与合规

### 11.1 用户认证与授权

- **JWT Token**：用户端和医生端独立 JWT，过期时间不同（用户端 7d，医生端 4h）
- **RBAC 角色控制**：`patient`、`doctor`、`admin` 三级权限
- **邮件验证**：注册需邮箱验证，医生账号需管理员开通

### 11.2 医疗数据安全

- **PHI 脱敏**：复用现有 [hipaa_service.py](file:///d:/PyCode/BrainDox/code/src/services/hipaa_service.py) 的 Presidio 脱敏能力
- **数据隔离**：用户只能访问自己的报告，医生只能访问分配到自己的待审核报告
- **传输加密**：全链路 HTTPS
- **审计日志**：所有医生审核操作写入 doctor_reviews + audit_trail

### 11.3 PDF 报告合规

- 每份 PDF 包含唯一报告编号和生成时间戳
- 医生电子签名（医生姓名 + 审核时间）嵌入 PDF
- 含免责声明："AI辅助生成，医生审核确认"
- PDF 使用 MD5 校验防止篡改（存储时记录 hash）

## 十四、关键设计决策记录

| 决策 | 选项 | 选择 | 理由 |
|------|------|------|------|
| 意图识别方案 | 微调BERT / LLM Few-shot / 纯规则 | LLM Few-shot + 规则兜底 | 灵活性高，规则兜底安全 |
| 轻症诊断模型 | GPT-4o-mini / 本地小模型 | GPT-4o-mini | 与现有系统一致，降低维护成本 |
| PDF 生成 | 前端生成 / 后端渲染 | 后端 Celery 渲染 | 可靠性高，支持异步重试 |
| 医生审核模式 | 逐份审核 / 批量审核 | 逐份审核 | 医疗场景需逐份负责 |
| 会话状态存储 | PostgreSQL / Redis | Redis | 低延迟，支持 TTL 自动过期 |
